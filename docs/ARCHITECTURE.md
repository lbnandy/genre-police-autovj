# AutoVJ integration

## Rhythm sources

`packages/link-client.cjs` reads bundled Carabiner at localhost port 17000. Only `status` requests are sent; AutoVJ never changes session tempo, phase or transport. Auto (the default) and Link start the component automatically. Selecting audio stops timing queries and restores audio detection; a component started by AutoVJ is kept for the rest of the app session and exits with AutoVJ. Peer discovery remains enabled regardless of playback or peer count. Healthy zero-peer sessions are never recycled. Owned helper exits and unresponsive TCP sessions recover with bounded retry backoff; externally owned processes are never killed. An already-running local bridge can also be used. The source selection and timing offset are machine settings, excluded from library exports. `prepare:link` builds the pinned source plus the UDP recovery patch and verifies an input/output build receipt before startup/packaging; the executable is unpacked under `native/bin`, and licenses/source are shipped separately under `resources/carabiner`. No system installation or user-selected executable is required.

`renderer/rhythm-clock.mjs` owns beat-source selection: Auto uses a valid Link peer and falls back to audio; Audio always uses DSP + BeatNet; forced Link reports disconnected without fallback. BeatNet runs internally only while listening with the audio source. Music response retains DSP events between beats; Link supplies tempo and a small beat accent, without mixing Link and BeatNet. Beat-driven mode accepts only Link beat crossings or particle-filter-decoded BeatNet beats. Beat-driven mode is the default; dynamic strength is the default for beat-driven mode. Fixed strength is 0.78; dynamic strength is 0.5 + 0.5 × sqrt(DSP energy), giving a comparable middle range and room for strong accents. Existing saved choices are retained. If audio beats are unavailable, beat-driven impacts wait rather than substituting DSP events. Silence stops impacts. Source/mode changes consume old peaks and clear envelopes; Link reconnects, phase jumps and suspended frames re-anchor without replaying missed beats. Stale worker messages are ignored after replacement. Positive Link offset delays visuals; negative advances them.

Link provides timing, not track identity, kick strength or a guaranteed playback state. Audio listening remains necessary. Enable global and deck LINK in rekordbox and verify the deck's beat grid. Peer presence does not prove that the audible deck follows Link. AutoVJ does not send or subscribe to shared transport commands. Tests cover real local Carabiner peers and model handover; rekordbox and venue output timing still need equipment testing.

## 0.1.0 interface

The console uses a frameless window, a draggable header and explicit window controls through the operator-only IPC boundary. `packages/messages.json` supplies four languages through renderer/main adapters. App-level `app.json.language` overrides legacy library preferences, so library switching preserves the chosen language. Fonts come from the original visualizer with language-specific Noto fallback order.

`standbyTheme: neutral` retains the original default visual, with an explicit `standby` scene flag. The stage shows STANDBY in every language and localized waiting text. Idle animation continues, and the normal text toggle remains authoritative. Existing custom standby choices remain supported. Version 0.1.0 is also distributed as a Windows x64 portable executable for feature review.

Text visibility, layout, `fullscreenCondensed` and DJ-name presentation are grouped in settings. Latin metadata uses DM Sans or Barlow Condensed; CJK reading fonts follow the desktop controller's script/context rules. The console's select-only comboboxes retain native selects as their value sources and use top-layer popovers so menus escape panel/dialog clipping. Interface SVGs are pinned, unmodified Google Material Symbols Rounded assets with retained Apache-2.0 notices. The console receives the complete GPU composition at up to 30 FPS; preview visibility is reported through sender-checked IPC. Brightness uses a black overlay to avoid filtering the entire text composition.

An absent app language preference means `system`; the resolved UI language comes from Electron's system locale at startup. An explicit preference overrides it, with unsupported system languages falling back to English as in the desktop visualizer. Public settings expose both the preference and resolved language.

`renderer/stage-geometry.mjs` preserves the original 920×400 landscape composition. Stacked portrait output uses a taller logical composition; the canvas and CSS backdrop share screen-covering overscan. The console lays out controls independently, uses equal-height settings rows and lets its preview fill remaining height.

The console has no fixed maximum content width, including on 1440p and ultrawide monitors. Branding uses the desktop's Orbitron 700; control copy and tabs use DM Sans/Noto. `renderer/output-frame-rate.mjs` adapts the pinned frame limiter: the library stores a 30/60/90/120/display cap (60 by default), optional 30 FPS stopped-standby mode and a console-only FPS readout. Active listening always bypasses standby throttling, even before track recognition. The stage reports measured rendered frames once per second through sender-checked IPC when diagnostics are enabled; it never adds diagnostics to audience output.

## Boundaries

The low-load profile is machine-local (`app.json.performanceMode`). Console broadcasts contain library deltas backed by revision/data-identity caches; large tables are virtualized. A persistent preparation worker owns one ONNX session per batch and releases it at batch end. PCM is read in bounded windows with globally aligned sinc coordinates. Native preparation streams supported decoder paths into PCM and computes overlapping spectrogram blocks using the pinned peak/hash functions. The NDI encoder runs on a separate thread with bounded async buffers; completed prior GPU readbacks are mapped without waiting. Rendering suspends when no visible preview, local output or external route consumes it.

`renderer/adaptive-resolution.mjs` adapts the pinned desktop controller's fullscreen resolution loop: 1.2 s warmup, 2 s measurement windows, two sustained low-work/missed-frame windows to lower canvas scale, twenty stable windows to recover, and levels 1/.9/.82/.76. It operates independently of FPS diagnostics. Session profiles include theme, viewport dimensions, DPR, text/layout and frame cap; no profile is shared across different display sizes. Native show/hide/minimize/restore events update `scene.outputVisible`, because Electron's disabled background throttling keeps `document.hidden` unreliable for this purpose. Hidden/minimized, blacked-out and stopped-standby output do not contribute samples. Pauses over 250 ms restart warmup. New libraries use `renderScale: "auto"`; existing numeric settings remain fixed. Only the main animation canvas backing store scales, leaving DOM typography and console controls at native resolution. `prepare-visuals.cjs` also extracts the original WeakMap CSS-write deduplication and retains the foreground CSS-variable 60 Hz update cap when regenerating text motion.

- `vendor/genre-police`: immutable, pinned source for visual geometry, textures, fonts, audio DSP, genre mapping and ONNX preprocessing. The desktop controller, lyrics, media sessions and desktop-device monitoring are never started.
- `vendor/vjvision`: immutable source for fingerprinting, alignment, Music Battery and Windows audio. No Qt UI, QML renderer or Qt deployment is used.
- `native/recognizer.cpp`: Media Foundation / PCM AIFF decoding, UUID-backed indexing, SQLite snapshots, an NDJSON control process and a bounded PCM pipe. `prepare-native.cjs` produces reviewable capture and matching adapters. Battery thresholds remain upstream constants.
- `app/main.cjs`: library ownership, sequential analysis queue, worker/process lifecycle, selected devices, IPC authorization, operator console, one authoritative offscreen GPU renderer and a separate local presentation window.
- `packages/texture-distributor.cjs`: bounded GPU-texture distribution to the console preview, local presentation and native sender. It retains each source texture until native GPU-copy acknowledgement and local imports are released.
- `native/video-output.cpp`: isolated C++ Spout / NDI video sender, fixed output dimensions and cadence, blackout, source-stall handling and route statistics. Machine-level format preferences are separate from library data; route switches reset to off at startup. See `VIDEO-OUTPUT.zh-CN.md` for output lifecycle, dependencies and receiver validation.
- `packages/analysis-worker.cjs`: whole-track preprocessing and model inference. 44.1 kHz mono → 16 kHz sinc resampling → 32,768-sample overlapping windows → MusiCNN mel features → 400 Discogs activations → arithmetic mean per class over non-silent windows → original genre mapping. No live tracker, artist priors or early stopping. Raw scores, model revision and window counts are stored.
- `packages/catalog.cjs`: bounded online requests during preparation only. Exact-version filtering, artist/title/duration checks, metadata-only queries, cached results and source scope. Album hints cannot masquerade as authoritative track-level genre.
- `renderer/stage.js`: one actual visual engine with the original snapshot transition, original CSS backgrounds and DOM ornaments. The guitar layer, typography fitting, long-title marquee and text motion/filter routines are extracted from the pinned original controller; that desktop controller is not executed. Genre heading, parent genre, track title, artist and artwork are retained by default. A text switch and independent side-by-side/stacked layout selector mirror the original presentation options. Only lyrics are removed from the stage metadata presentation. Stable theme keys prevent repeated transitions. Theme colors, stage DOM and source resources stay together in imports.

## Audio and scene events

WASAPI captures one explicitly selected endpoint and pair of channels. Both fingerprint matching and the raw PCM bridge consume that same signal. Each binary frame has four little-endian uint32 values: magic `0x47504156`, sample count, rate `44100`, sequence; followed by float32 mono samples. Buffers are bounded in native capture, the pipe parser, Electron IPC and the AudioWorklet. Render delays discard old audio instead of accumulating seconds of latency. No audible monitoring route is created.

The stage reuses Genre Police AudioEngine's DSP through an adapter that disables its desktop capture and device monitor. A muted AudioWorklet feeds its two analyzers. A separate worker low-pass filters and decimates the same PCM to 22.05 kHz for internal BeatNet; failing that branch does not stop the DSP or output.

Music Battery confirms first tracks and changes. Tentative / mix-hold messages update the console only. A confirmed track UUID resolves saved genre and optional visual override. Same theme keys do not retrigger transitions. Blackout is a final opaque layer. Manual lock remains active across input loss, while obsolete track metadata is cleared. Ten seconds of silence returns to standby; thirty seconds without evidence for the current song clears stale automatic attribution. The underlying battery rules are unchanged.

## Library identity and portability

Equipment is now app-local: `app.json.equipment` stores `deviceId`, `channelStart` and `displayId`, migrated once from the active legacy library. `settings()` overlays it for the console and stage; library switching and imports cannot replace it. Valid channel pairs come from the actual endpoint channel count, including mono/odd final channels. `keepAwake` also belongs to app config. `performance-session.cjs` manages an Electron display-sleep blocker only while listening or visible output needs it, input-health timing and a bounded in-memory diagnostic event list. Reports are written only on explicit export and omit music/DJ names, device IDs and source paths.

The output controller remembers mode, display and window bounds. A renderer crash creates a replacement source/presenter pair and waits for its first scene to be applied before restoring output. Track state and blackout stay in main. A burst exceeding three recovery attempts within 30 seconds stops auto-recreation; the operator can use Restart visuals. Hiding the local window leaves external senders active, including wake protection and source rendering. External sending overrides stopped-standby throttling and the local frame cap; internal adaptive canvas resolution remains independent of the fixed video format. Quitting releases wake protection and stops the sender. Hardware-loss and real-driver behavior still require venue testing.

Track removal retains one `.undo-<library-id>` directory next to the active library, excluded from library enumeration and USB exports. A track-data hash prevents undo from overwriting later edits. Undo snapshots SQLite through the existing native backup API so uncheckpointed WAL content is restored, then atomically swaps the complete replacement. It preserves the current library's name, DJ profile, presets and settings. Recovery journals cover interrupted remove/undo swaps; deleting a whole library also removes its undo snapshot. `openLibraryFolder` checks and directly opens the absolute data directory with `shell.openPath`, handling its OS failure result.

`library.json` owns stable library and track UUIDs, metadata and manual choices. Fingerprint `song_name` stores the UUID; SQLite's integer song_id is only an internal join key. Relocation does not depend on the original path. Analysis uses decoded-PCM SHA-256 to detect exact duplicate audio; duplicate imports reuse the existing UUID and preserve prior manual choices. Encoded versions which decode differently remain distinct rather than risking a wrong-version merge.

`analysis/<uuid>.json` stores full scores and source evidence; covers use relative paths. Exports omit source paths, machine device IDs and local cache, and take a consistent SQLite backup. Imports validate UUIDs, relative paths and regular files, copy into a staging folder, then atomically install an independent local library. Original music is never modified. Reanalysis commits individual tracks; interruption leaves pending/failed tracks available for retry. Old manual choices survive replacement of automatic evidence.

Multiple imported packs are separate named libraries in 0.1.0. The operator explicitly selects the library for a set. Export includes all custom visual presets. Settings and data are entirely separate from both original projects.

## Version upgrades

The importer refuses dirty upstream checkouts and locally modified vendored source. Without `--apply`, it writes only `.upstream-staging/candidate-*`. Each candidate contains file-level hashes, changed files and regenerated adapter boundary checks. Applying backs up the previous complete vendor tree and generated adapters under `.upstream-staging/rollback-*`; restore those files with AutoVJ closed to roll back. The source repositories remain untouched.

After application: rebuild native code, verify source/resources, run unit and native replay tests, and inspect electronic, acoustic, classical and guitar scenes. Production builds always ship fixed source revisions. Updated visuals do not invalidate prepared AI results; a changed model, preprocessing definition or fingerprint schema requires an explicitly versioned reanalysis/migration instead.

The library table footer owns a fixed-height activity slot for preparation, listening/maintenance and removal undo. Main-process batch counters retain the original total, settled/succeeded/failed counts and cancellation state through worker handoffs and renderer reloads. The bar fills cumulatively by settled track count; per-track AI percentages remain in the phase label. Cancellation never treats cleared queued tasks as completed. Batch results are scoped to their library and retained only for the current app run. Status updates preserve existing nodes and keyboard focus; long metadata is ellipsized. Analyze and Stop share one reserved toolbar slot, while selection/removal actions remain at the table footer.

### Link recovery validation

During a rekordbox Link toggle reproduction, an instrumented upstream build reported Windows UDP error 10054, then stopped receiving on that socket while its TCP status endpoint remained responsive. A fresh participant could join rekordbox, but measurement against the old participant failed. The upstream socket completion path did not schedule another receive on error. The bundled patch repairs that path instead of periodically restarting sessions with no peers. Separately, the old one-shot launch flag prevented recovery after a helper process exit; the client now supervises owned processes throughout the enabled lifetime.

`native/tests/link-udp-recovery.cpp` covers receive recovery after error 10054 and empty datagrams. `scripts/build-link-tests.ps1` builds the native tests. `scripts/qa-link-lifecycle.cjs` runs real Link participants through repeated enable/disable, external process restarts, a killed owned bridge and a delayed peer arrival. Set `LINK_SOAK_MS` to extend the idle interval (default 120 seconds). This bounded soak is not an overnight or venue timing certification. JavaScript tests cover exact 0/1 peer transitions, TCP reconnection and repeated bridge crashes. Rekordbox playback is not required for discovery; audio is only needed for visual silence gating.

### BeatNet decoder verification

The audio beat source retains the upstream beat-stage particle filter without the meter stage. EDM timing accepts the last prior-population frame as a 20 ms boundary tolerance. Three consecutive model-activation intervals within two frames establish a short periodicity lock; Fresh activation above 0.4 acquires and confirms the lock. At most two consecutive weaker activations above 0.25 can support expected beats within two frames, requiring a threshold crossing and a rise of at least 0.08. Weak evidence cannot acquire a tempo or maintain the lock without renewed strong evidence. Off-grid activations do not add impacts while locked, and the lock expires after two periods without aligned evidence or 2.5 periods without strong aligned evidence. No beat is synthesized in silence. Particle count is restored after strong-observation rejuvenation to correct the upstream discarded deletion. `scripts/compare-beatnet-reference.cjs` compares events and particle-state checksums frame by frame against the pinned Python source through `scripts/compare-beatnet-reference.py`, using the same random draws and population correction, with EDM timing disabled through the internal `edmTiming:false` constructor option. Pass the upstream source file and optionally a JSON array of `[timeMs, beatProbability, downbeatProbability]`. This is a beat-stage port comparison, not end-to-end equivalence to the complete Python package or a musical-accuracy benchmark. The default EDM timing adaptation is tested separately for narrow peaks, off-grid fills, silence and tempo changes; it is not claimed to reproduce upstream events.

### Bundled BeatNet+

Development and packaged builds use the same bundled BeatNet+ generic ONNX weights, 1764-sample / 144-band features, one-hop alignment delay, four-layer recurrent state, and `edmTiming: 'boundary'`. No environment variable is needed. Packaging verifies the model hash and fails if it is absent or changed; runtime errors are surfaced without silently selecting the older BeatNet model.

### Offline video export

Track actions open a dedicated export dialog. Export settings are whitelisted and saved separately in app configuration. The job snapshots the library theme, metadata and per-library images; later console changes do not alter its rendering. It uses the pinned standalone FFmpeg executable bundled by `ffmpeg-static`, never a developer machine's PATH.

Multi-selection opens the same dialog in batch mode, with shared options and a selectable preview track. The batch snapshots each track's visual theme and processes tracks sequentially. It reserves unique sanitized filenames with exclusive creation, never overwriting existing videos. Missing audio and per-track failures are reported in the queue without stopping subsequent tracks. Cancellation removes only unfinished output, preserves completed videos and marks unstarted tracks cancelled. The dialog may be closed while exporting; its task entry reopens the current queue. Queues are in-memory and do not resume after application exit.

Automatic encoding first tests a real frame through WebCodecs with hardware acceleration requested. Electron shared textures feed this encoder without transferring the full image to the main process. Annex B H.264 packets are streamed to bundled FFmpeg for AAC encoding and MP4 muxing. If initialization is unsupported or fails, full exports probe FFmpeg NVENC with eight frames at the requested dimensions, then fall back to libx264. Software compatibility can be selected explicitly; bitmap previews use libx264 ultrafast. The three quality levels use shared profiles in `export-quality.json`: WebCodecs targets 8 / 12 / 20 Mbps for 1080p60 and 5 / 8 / 12 Mbps for 1080p30, with smaller profiles for 720p and square output. The UI size estimate uses the same profile as the encoder. NVENC uses P5/HQ VBR-CQ (24 / 21 / 18); libx264 uses CRF (24 / 21 / 18). WebCodecs uses realtime latency mode to keep per-frame encoder delivery bounded. These are different quality controls, not a promise of identical bitstreams or file sizes. A mid-export encoder failure is reported and the partial file is removed; users can retry in software mode.

FFmpeg decodes aligned 44.1 kHz DSP and 22.05 kHz model streams to temporary files. A worker processes every model hop sequentially using sample time, without the live model queue's drop/reset policy. This uses the existing causal BeatNet+ model and beat-stage particle filter ahead of rendering; it is not the upstream offline DBN decoder. A one-track session cache avoids repeated inference while adjusting visual settings.

A separate hidden stage receives sample-clock spectra and rhythm events. It reuses the live DSP, visual renderer, typography and impact pipeline, with seeded randomness, fixed resolution and CSS/WAAPI animation time driven by the frame timestamp. Frames are sampled serially at n / fps and submitted with bounded backpressure. Low throughput increases rendering time rather than dropping frames. Clip previews use a bounded three-second warm-up; their persistent particle/DSP history may differ from the same position in a full-song export. Full exports simulate from zero. Long-song and broader GPU validation remain necessary.

The export compositor runs up to 240 Hz, independently of the output FPS. A 32-bit frame token in a four-pixel gutter identifies the committed surface; stale surfaces are ignored, and the gutter is removed before encoding. The layout retains the requested video dimensions. The shared-texture path reads only this small token region, crops the GPU VideoFrame and transfers compressed packets. Its isolated preload exposes no console or live-input actions. The fallback consumes the `paint` bitmap directly as BGRA instead of a second `capturePage` readback. One outstanding frame/pipe write overlaps encoding with the next frame's rendering, with bounded memory, explicit texture release and cancellation of pending capture. This avoids relying on a fixed number of animation-frame waits or globally disabling browser frame pacing.

A temporary sibling file is atomically renamed only after encoding succeeds. Cancellation terminates the encoder/worker and removes partial output. A normal app exit waits for cleanup. Export is separate from the live shared-texture/Spout/NDI routes and does not consume Link timing.
